drosaka Voice Instrument — Spec v1
Oct 29, 2026 · @Wiley
Purpose and concept
A private Ableton instrument that turns one recorded vocal phrase into a synchronized crowd of voices, then assimilates that crowd, voice by voice, into a military-codec robot voice. Built for the drosaka tracks only, so the sound stays unique to the persona.
The gesture: one real voice in the center, a crowd of clones filling in around it, the codec infecting the crowd one voice at a time until the real voice falls last. At the drop, cut back to the single human voice.
First use: track one, "They stole your mess and made it a meme" (looped) and "Put your phones down, get your hands up" (at the drop). Series subhead: "Beats for the walkaway."
Voice bank
The instrument holds a bank of pre-rendered voice stems (e.g. one phrase run through many ElevenLabs voice conversions), all time-aligned to the same source performance.
• Drag-and-drop audio files into the device, Simpler-style; any number of stems, designed for up to 20
• Per-voice mute and solo
• One stem is selectable as the primary voice; it sits dead center and the crowd builds outward from it
• On import the plugin analyzes each stem (average pitch and formant centroid) and auto-sorts the bank into a frequency array, low to high; sort axis switchable
• Presets save the whole bank with audio embedded, so a phrase-bank travels with the Live set
• [added Oct 30, Wiley] Stem alignment, for overlapping separate takes: on import each stem is auto-aligned to the primary by whole-stem time shift (takes only need to be close; no time-warping). Matching uses the syllable-rhythm envelope, so different voices of the same words align; when confidence is low (e.g. different words) the stem is left in place and flagged. Each row shows its waveform on a shared timeline over a ghost of the primary: drag to nudge (shift = fine), double-click to reset to the auto position, "Align all" re-runs against the current primary. Offsets save with the set.
Controls
A small set of knobs, all MIDI-mappable and automatable. All changes to voice count and position crossfade smoothly, never hard-switch.
Control
What it does
Position
Scans a window along the frequency-sorted array: low = chorus of deep voices, high = chorus of thin voices; sweep mid-phrase to morph the crowd
Count
How many voices sound (0 to all), building symmetrically outward from the primary in left/right pairs; sets the window width
  [decided Oct 30, M2] "Outward" = neighbours in the sorted array, nearest first; at the array's edge the window extends on the side that has voices. Each pair fades in together as the knob turns (continuous, no steps). Overall level is normalised as voices are added (gain ÷ √(sum of squared voice gains)) so loudness stays roughly even. Until Spatial mode exists (M6), each pair pans wider the further it sits from the primary, lower-sorted member to the left (interim "radiate").
Spatial mode
How chosen voices arrange in the stereo field: radiate from center, bounce around, others TBD; tempo-synced where motion is involved
  [decided Oct 30, M6] Modes as built — Radiate (pairs fan out, wider with distance); Bounce (every division each audible voice hops to a new slot; slots evenly spaced edge to edge and re-dealt per division from a fixed seed, so the same bar always looks the same); Orbit (voices circle the field, one revolution per division) and Swap (the radiate layout mirrors L<->R every division) are Claude's proposals for "others TBD" — keep, change or cut. Primary stays dead centre in every mode. Rate menu: 4 bars … 1/16, plus 1/4T 1/8T 1/16T. Pure panning for now (depth cues still open). Hops glide 15 ms.
Encode count
Spreads the codec across the voices, 0 to all, one voice at a time at full strength; order is a fixed-seed random scatter across the field so it jumps around the head; the primary voice is always last
  [decided Oct 30, M4] Order alternates left/right of the primary (by sorted-array side, which is also the panning side), random within each side from a fixed seed; primary last. Encode counts only the audible voices (inside the Count window and not muted, or soloed): 0–100% = 0 to all audible voices, taken in the fixed order filtered to those voices, so every step is heard (Wiley, Oct 30). A voice's place in line can shift as Count changes; changes glide. Silent voices wait dry, except at 100% where everything is encoded so voices fading in arrive on the codec.
  [decided Oct 30, M4] Codec output is DC-blocked at 50 Hz (impulse-train DC was summing coherently across encoded voices, +3 dB) with a fixed +1.6 dB make-up, so a fully encoded crowd sits within ~0.5 dB of the dry crowd. The M3 test switch is gone.
Codec: bit rate
Quantization severity of the LPC coefficients, clean to barely intelligible
Codec: frame drop
Simulated packet loss
Codec: pitch lock
Excitation pitch fixed, free, or tracking
The codec runs as one encoder instance per voice with shared settings (about 20 channels at 8 kHz; CPU is not a concern).
  [decided Oct 30, M3] Pitch lock modes as built — Fixed: monotone at the voice's own analysed median pitch, consonants still hiss. Tracking: follows the voice's pitch contour (median-smoothed), consonants hiss. Free: raw pitch detector, unsmoothed, held through consonants and never switching to noise, so everything buzzes and the pitch jumps where the detector lands. (Free was undefined in the spec; this reading needs Wiley's ear.)
  [decided Oct 30, M3] Frame drop: 0–100% = 0–50% of transmitted frames lost, in bursts. A lost frame replays the last good one once at half level; a second loss in a row is silence. Bit rate also lowers the frame rate above ~60% (frames repeat 2× above 60%, 3× above 85%), alongside coarser coefficients, gain and pitch steps.
  [decided Oct 30, M3] Every voice's codec runs continuously; dry voices are delayed to match it, and the plugin reports that delay (~39 ms) to Live, which compensates so notes stay on the grid.
Spread (pitch)
One playable knob that moves the crowd from unison to chorus to chord to cluster, continuously, for builds.
• Each voice has a continuous pitch path: 0 cents, then a detune (cents), then its chord interval, then its cluster position (voices a semitone apart). Spread is a position along that path, so every voice glides and nothing steps
• Chord interval set chosen from a menu (fifths, minor triad, stacked fourths, etc.); outer voices in the array take the widest intervals; the primary voice stays unpitched in the center
• Snap sub-control shapes the curve: how strongly pitches linger on chord tones and rush through the in-between zone; 0 = pure portamento, full = near-stepped
• Shift range limited to about ±7 semitones to keep speech artifacts tolerable; the codec covers the rest
• Typical build: automate Spread and Encode count together over 8 to 16 bars
  [decided Oct 30, M5] As built: stations at 0 / ⅓ / ⅔ / 1 = unison, chorus (±7–30 cents, wider and slightly irregular further out), chord, cluster (pair k at ±k semitones). Chord menu: Fifths, Minor triad (default), Major triad, Stacked fourths, Minor 7th, Octaves; up-side voices take the chord's upper tones and down-side voices its lower ones, narrow to wide; past the list they repeat an octave out. Dry voices are pitch-shifted by PSOLA (formants kept, timing kept) within ±7 st: each station is folded into ±7 by octaves and the voice glides between folded stations, so it never jumps mid-sweep. Encoded voices transpose the codec's excitation and play the full interval (up to ±24), which is "the codec covers the rest" — so a voice can land an octave away from its dry pitch when it gets encoded. Snap is a tanh curve between stations (0 linear, 1 near-stepped). [superseded Nov 1 by Harmony Spread, below]
Instrument behaviour
It is an instrument, not an effect: it sits on a MIDI track and plays on notes.
• Trigger: a MIDI note fires playback; note pitch does not transpose, trigger only
• Slicing: manual slice markers on the phrase; each slice maps to a key; because all stems are aligned, one marker cuts every voice, so one key fires that word across the whole crowd
  [decided Oct 30, M7] Markers sit on the aligned phrase timeline (so they respect each stem's alignment offset). N markers make N+1 regions; region k plays on C3 + k (C3 = MIDI 60, Live naming); any other key plays the whole phrase. A slice plays from its start marker and fades out (3 ms) exactly on its end marker. Editing on the top waveform: double-click adds, drag moves (can't cross a neighbour), right-click deletes.
• Tempo sync (in v1): the device reads Live's transport; spatial motion (bounce etc.) can lock to note divisions, and the encode-count stepping can quantize to the beat instead of free-running
  [decided Oct 30, M6] Grid events land on the musical time of the output (the ~39 ms latency is subtracted, matching Live's compensation). With Live stopped, an internal clock at the last tempo keeps motion running. Encode steps (Free, 1/16 … 1 bar): on each grid line the encoded count latches to the whole number of voices the knob asks for, so voices flip on the beat (several at once if the knob jumped).
• Presets: bank + slices + knob states saved with embedded audio
  [decided Oct 30, M7] The Live set itself carries the audio: plugin state is a binary tree with each stem embedded as 24-bit mono FLAC (lossless; roughly half the size of raw), plus offsets, flags, slices and every knob. "Preset" menu saves/loads the same thing as a .dvoice file. Older sets (file paths) still open and are re-saved with audio embedded.
• Crowd/codec knobs stay live while playing, so a performance can grow and infect the crowd in real time
Pattern mode (tempo-synced retrigger)
Two ways to play: Manual, every hit from the keyboard as above, or Pattern, where one key press starts a tempo-locked walk through the phrase's slices. The core idea: the line was spoken freely, not to a beat; the slices become steps, and the pattern plays them in order on the grid, so a loose phrase lands on the beat. Chopped-and-screwed behaviours are rules applied on top of that walk. A handful of built-in patterns, not a full sequencer.
Pattern
Behaviour
Walk
One slice per step in order, on a chosen division (1/4, 1/8, 1/16, triplets); the base quantize-speech mode
Repeat
Each slice fires N times before advancing (chopped: "they they they stole")
Stutter
Beat-Repeat style on the current slice: retrigger while the slice length shrinks, then advance
Screwed
Slice pitched down and time-stretched to fill the step; Drop amount in semitones
Skip / Rewind
Probability of stepping back a slice or leaving a step silent
Ratchet
Division halves every bar or beat, accelerating into a drop
Random
Slice order shuffled, fires on the division with a Density knob
• Common knobs: Division, Gate (hit length, tight to ringing), Density, Repeat count, Drop, and a Latch toggle (keeps running after key release until stopped)
• Each slice is stretched or truncated to its step length so the phrase stays on grid regardless of how it was spoken
• Holding a slice key while a pattern runs jumps the walk to that slice on the next step
• Pattern timing follows Live's transport so it stays locked to the groove engine clock
  [decided Oct 30, M8] As built: Play mode Manual/Pattern. In Pattern, any key starts the walk on the next Division line (a slice key starts it from that slice); holding a slice key mid-walk jumps there on the next step; releasing every key stops it unless Latch is on. Hits land sample-exactly on Live's grid. Fitting: a slice shorter than its step is time-stretched to fill it (up to 2x, PSOLA, pitch unchanged), a longer one is truncated; Gate (5-100%) sets how much of the step sounds. Screwed fits each slice exactly to its step and drops it by Drop (0-12 st, default 5). Stutter: the slice on one step, then Repeat-count retriggers of its opening in the next, then on. Skip/Rewind: Density is the chance of a skip (silent step) or rewind (back one slice), half each; repeatable. Ratchet: division halves every bar, down to 1/16 of it, counted from when Ratchet is selected. Random: a fresh shuffle of the slices each pass; Density = chance a step fires. Division: 1/4 1/8 1/16 1/32 + triplets. Switching pattern restarts its count. Pattern changes are deterministic (same pattern plays the same way). [superseded Nov 1 by Pattern schemes, below]
Technical notes and open questions
Build in JUCE, ship AU and VST3 from one codebase (Ableton on Mac loads both; Windows loads VST3 only). Codec core: LPC analysis around 10th order at 8 kHz, hard-quantized coefficients, resynthesis with a pulse or saw excitation; quantization and frame drop are what make it sound like radio rather than a vocoder.
Reference sounds for the codec: LPC-10 and STANAG 4591 MELP demos (YouTube); musical cousins are Kraftwerk "Numbers" and Laurie Anderson "O Superman". Reference for chopped vocal technique: Green Velvet "Flash", Blawan "Why They Hide Their Bodies Under My Garage".
Open questions:
[~] Full list of spatial modes beyond radiate and bounce — Orbit and Swap proposed (M6), awaiting Wiley's ear
[x] Depth cues for outer voices — Depth knob (default 0 = pure panning): outer voices by their place in the crowd get up to -6 dB dry, +12 ms pre-delay and a shared reverb send; the primary never. Based on crowd position, not moving pan, so Bounce/Orbit never bend pitch.
[x] Dry primary path — "Keep primary human" switch: Encode never takes the primary (100% = every voice but the real one).
[x] The drop — a dedicated DROP switch (automatable, MIDI-mappable): the crowd fades out (50 ms) and the primary comes back human and dead centre, whatever Count/Encode/Spread are doing.
[x] Shared transport — the device follows Live's transport (tempo, position, latency-compensated), so it's locked to anything else in the set, the groove engine included. A direct sf-transport link would only matter outside Live.
Build order and working method
Build in milestones ordered by what is audible soonest. One milestone per chat session: build it, Wiley tests it in Ableton Live, reports what he heard, and the next milestone does not start until the current one sounds right. Corrections to the spec happen as they are found.
Milestone 0, toolchain: Xcode is already installed (used for the iOS Roadbook app). Add CMake and JUCE via Homebrew/git clone, then a one-line build script that compiles AU and VST3 and copies them into ~/Library/Audio/Plug-Ins/Components and /VST3 so a rescan in Live picks them up. Claude Code runs the builds from the laptop; the chat cannot produce plugin binaries itself.
1. Sample player: load one stem, trigger on a MIDI note, loads as AU and VST3 in Live. Proves the JUCE build and plugin loading
2. Voice bank: drag-drop import, auto-sort by pitch/formant, primary selection, mute/solo, Count knob with smooth crossfades. First time the crowd is heard
3. Codec on a single voice: LPC analysis/resynthesis with bit rate, frame drop, pitch lock. Tune by ear until it sounds like radio, not a vocoder
4. Encode count: one encoder per voice, fixed-seed scatter order, primary last
5. Spread: pitch paths, chord menu, Snap
6. Spatial modes and tempo sync
7. Slicing and presets with embedded audio (slot in earlier if their absence gets annoying)
Rules for the build chat: keep the spec as the source of truth and update it when a decision changes; prefer small testable commits; never add a feature not in the spec without asking.

Additions (Nov 1, Wiley's requests)
• Slice markers automatable (revised Nov 1, Wiley): each marker has a home position (waveform-edited, saved in state, seconds) plus an automatable offset parameter "<note> slice offset" (−100%…+100%, 0 = middle of the lane: +100% reaches the next marker's home or the end of the audio, −100% the previous marker's home or the start). Marker k always starts key C3+k+1; markers can't overtake; inserting/deleting renumbers later markers and carries their offsets. Earlier formats (bank seconds; absolute share-of-phrase parameters) are converted to homes, sorted.
• Autotune: Tune (0–100%), Root (C–B), Scale (Root = monotone on the root in each voice's own octave; Minor; Major = snap each period to the scale). Dry voices via PSOLA per period; encoded voices via the codec excitation; applies to every voice including the primary; stacks with Spread and Screwed.
• Harmony Spread (Nov 1, Wiley: "now that we have autotuning, incorporate it into the chorus system"; replaces the M5 relative intervals). The crowd sings real notes on the Tune root; the primary stays human (Tune still applies to it). Stations: natural (untouched) / chorus (every crowd voice on the root, in the octave nearest its own register, detuned ±8–30 cents wider further out, drifting, keeping 15% of its own wobble) / chord (Chord menu tones on the Tune root, read as pitch classes; outer pairs take the later tones) / cluster (neighbouring steps of the Tune scale, chromatic in Root mode). Every target is voiced in the octave nearest the voice, so no voice moves more than 6 st, and dry and encoded voices sing the same notes (the old "codec covers the rest" octave jump is gone). Each pitch period: the voice's median moves onto the target and the deviation around it is ironed out (Tune adds correction if stronger). Harmony keys C1–B1 (MIDI 36–47): held notes become the chord, overriding the menu and lifting Spread to at least the chord station; spread low-to-high across the crowd by pitch; they don't trigger the phrase or patterns. DRIFT (0–100%, default 35%) is a slow per-voice wander, up to ±28 cents, full at chorus and half at chord/cluster. Rows show the note each crowd voice sings.
• Pattern schemes (Nov 1, Wiley: "play the entire sliced sample starting with the triggered slice... one knob controls how many slices get played so I can slowly expand the phrase, another stutters... schemes that use the entire slice palette, especially techno"; replaces the M8 pattern types). One key starts a loop through the phrase from that key's slice, running on through every slice (wrapping); non-slice keys start at the top. Shared macros, the same in every scheme: LENGTH (slices in the loop from the trigger slice, 1..all; a change waits for the loop's restart), FILL (hits per bar spread Euclidean, first on the downbeat; rests don't skip phrase material), STUTTER (rolls of 2/3/4/6 retriggers of a slice's opening; ~18% of hits at full in ordinary bars, 2× in bar 4 of every 4, 3× in bar 8, plus a strong push on the last beat of every 4 bars), VARIATION (per-bar mutations: skip, repeat the last slice, jump ahead two, reverse, drop a fifth, plus quiet ghost hits on rests; bar 4 of every 4 strays 2×, bar 8 3×; repeats every 8 bars). Plus SWING (off-steps of straight 1/8–1/32 grids up to half a step late, shown as 50–75%; not on triplets) and ACCENT (beats full, "and"s −30%, 16ths −55% at full; rolls crescendo). Schemes: Phrase (in order; the loop restarts on a bar line once it has had room for all its slices, so a long phrase spans 2/4/8 bars); Anchor (trigger slice on every beat, the rest of the loop between); Offbeat (only the "and"s, stab gate 45%, Fill picks which); Rotate (each bar starts one slice later); Polymeter (the loop ignores the bar line); Ping-pong; Call & answer (a loop's worth of bars of phrase, then the same of the trigger slice chopped at half gate, every other hit doubled); Shuffle (new order each bar, repeating every 8 bars); Screwed (two steps per slice, fitted and dropped by Screw Drop); Build (division halves every bar from when it starts, 4 times). Everything rhythmic is computed from the song position, so the same bars always play the same way. Reversed hits play the slice backwards from its end at normal speed. Pattern hits start on the slice's first sound and end on its last (primary voice, 30 dB under its peak, 5 ms kept, never trimming more than 60% of the slice), so stabs of a slice that opens with a pause still speak. Offbeat stabs may ring for their whole eighth. Grid: SPACE RATE SCHEME DIVISION / LENGTH FILL STUTTER VARIATION; GATE, SWING, ACCENT and SCREW DROP sit in the Performance panel. Division default 1/16. Old sets: Walk/Repeat/Stutter/Skip-Rewind → Phrase, Screwed → Screwed, Ratchet → Build, Random → Shuffle; Density and Repeat count are gone. Assumes 4/4.
• The first marker starts the usable phrase (Nov 1, Wiley: "the slice before the first slice marker should not be considered as it's always just dead space"). Audio before it is never played: N markers make N slices, marker 1 starts C3 (so every slice key moved down a semitone from the earlier builds), the last slice runs to the end of the audio, and any other key (and a pattern started from one) plays from the first marker to the end. Offset parameters are renamed to match: "C3 slice offset" … "D4 slice offset" (same IDs, so automation stays on its marker). The dead space is dimmed on the waveform. With no markers, the whole stem plays as before.
• Banks (Nov 1, Wiley: "build the idea of banks into the vst... a set of stems and parameter adjustments... a knob could control which bank is active"; option A, 4 banks, switch on the bar, play mode per bank). One instance holds 4 banks. Each has its own stems, primary, alignment, slice markers (homes) and settings: every parameter except BANK, REC and DROP (so Play mode, Latch, Scheme, Tune root… are per bank). BANK (1–4, first parameter, automatable, MIDI-mappable) picks one; the change lands sample-exactly on the next bar line (4/4) while Live plays, and at once when it's stopped. Leaving a bank keeps it exactly as left, tweaks included (no store/revert); a bank used for the first time carries on with the current settings. On a switch, recalled settings reach the DSP on the line and the host from the message thread right after, so Live sends them to a controller mapped with Live's MIDI Map (the plugin's own MIDI learn can't send feedback). Automation in the arrangement still wins over recalled values. What's sounding fades (3 ms) on the line; a running pattern restarts from the new phrase's first slice (or a held slice key) on the line, or stops if the new bank is in Manual. Edits go to the bank they were made on. State v5 saves every bank (audio embedded); older sets open into bank 1. Header shows 1–4: lit = playing, pulsing = waiting for the bar, dim = empty.
• Stem gain trim (Nov 1, Wiley: "a gain adjustment for each stem that can offset each stem's relative value"). Each stem row has a GAIN cell, −24…+12 dB (default 0): drag up/down (0.25 dB per pixel, Shift 0.05), double-click for 0 dB. It scales the stem's output after Count, dry and encoded alike, glided over ~50 ms. Saved with the set, per bank (it's part of the bank's material, not a parameter).
• Stem outputs (Nov 1, Wiley: "output each stem as an individual channel so I can create an audio track with the input from one of the stems"; then "the stem should play from drosaka voice as well as send to an audio track to add effects at 100% wet"). Besides the main stereo out, the plugin has 16 stereo outputs "Stem 1"…"Stem 16". Stem N (its place in the bank, import order) is always copied to output N as heard in the mix (gain trim, Count, encode, pan, Depth level/pre-delay; not the shared Depth reverb) and keeps playing in the main mix, so the outputs work as sends. Each row's OUT button shows N; lit, the stem plays only on its own output and leaves the main mix (and the reverb). Saved with the set, per bank. If the host hasn't enabled an output, a lit stem stays in the main mix rather than going silent. Stems past 16 have no output. Removing a stem renumbers the ones after it.
• Recording: a Sidechain input bus (stereo, summed to mono) feeds a REC parameter; takes up to 60 s, trimmed (30 ms before first sound, 80 ms after last; gate -30 dB under the take's peak and above -70 dBFS), saved to ~/Music/drosaka Voice/Takes/*.wav, added and auto-aligned, embedded in the set.
